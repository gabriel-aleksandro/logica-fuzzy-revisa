Lógica Fuzzy: decidindo com o "mais ou menos"

Como transformar regras de especialista, escritas em linguagem natural, num sistema que classifica 1.599 lotes reais de vinho e ajuda o gestor a decidir o que vira rótulo Premium.

Integrantes: Gabriel Aleksandro de Paula [198327], Pedro Yang Kim [284031], Nome do Integrante 3, Nome do Integrante 4

Neste artigo:TeoriaEstudo de casoPythonVantagens e limitesUso em SAD

Pergunte a um enólogo se um vinho com 11,4 % de álcool é "alcoólico" e ele provavelmente vai responder: mais ou menos. Pergunte a um computador com uma regra do tipo alcool >= 11.5 e a resposta será um "não" seco. Um décimo de grau acima e vira "sim". Essa fronteira rígida é confortável para o código, mas é estranha para quem decide. A lógica fuzzy existe para preencher esse espaço entre o sim e o não.

Neste artigo vamos construir, do zero, um sistema de inferência fuzzy que apoia uma decisão real de uma vinícola: para onde mandar cada lote produzido. Usaremos dados públicos de 1.599 vinhos tintos portugueses avaliados por provadores, implementaremos tudo em Python e, no fim, discutiremos como o resultado vira informação para decisões operacionais, gerenciais e estratégicas.

01 · FUNDAMENTAÇÃO TEÓRICAConjuntos com fronteiras graduais

A lógica fuzzy foi proposta por Lotfi Zadeh em 1965. Na teoria clássica, um elemento x pertence ou não a um conjunto A. Na teoria fuzzy, ele pertence com um grau entre 0 e 1, dado por uma função de pertinência μA(x).

μA : X → [0, 1]     μalto(11,4 %) = 0,67

Isso não é probabilidade. Dizer que o vinho é "alto" com grau 0,67 não significa 67 % de chance de ele ser alto; significa que ele é parcialmente alto. A incerteza aqui está na fronteira do conceito, não no acontecimento.

Variáveis linguísticas

Uma variável linguística é uma grandeza numérica descrita por palavras. "Acidez volátil" vira {baixa, média, alta}, cada palavra com sua função de pertinência. As formas mais usadas são triângulos e trapézios, porque são fáceis de explicar e de calibrar. Os termos se sobrepõem de propósito: é nessa sobreposição que mora a suavidade do sistema.

Operadores

Os conectivos da lógica clássica ganham versões contínuas. No sistema de Mamdani, o mais usado em SAD, adotamos:

  • E (interseção): μA∧B = mín(μA, μB)
  • OU (união): μA∨B = máx(μA, μB)
  • NÃO (complemento): μ¬A = 1 − μA

Como o algoritmo funciona

Um sistema de inferência fuzzy do tipo Mamdani (Mamdani e Assilian, 1975) executa sempre as mesmas quatro etapas:

  1. Fuzzificação. Cada entrada numérica é convertida em graus de pertinência para cada termo linguístico.
  2. Avaliação das regras. Cada regra SE … ENTÃO … tem força igual ao mínimo dos graus dos seus antecedentes. O conjunto de saída da regra é "cortado" nessa altura (implicação de Mamdani).
  3. Agregação. As saídas de todas as regras são unidas pelo máximo, formando uma única área.
  4. Defuzzificação. A área é convertida num número. O método mais comum é o centroide:
y* = ∫ y · μ(y) dy  /  ∫ μ(y) dy

Existe também o modelo de Takagi-Sugeno, em que cada regra produz diretamente uma função das entradas e a saída é uma média ponderada. Ele é mais eficiente computacionalmente, mas menos interpretável. Neste tutorial usamos Mamdani porque, em apoio à decisão, poder mostrar ao gestor por que o sistema chegou a um número é tão importante quanto o número.

02 · EXEMPLO PRÁTICOA vinícola que precisa decidir o destino de cada lote

Imagine uma vinícola que produz centenas de lotes de vinho tinto por safra. Cada lote passa por análises físico-químicas de rotina. Os provadores especialistas, porém, são caros e lentos: avaliam por amostragem. A gestão precisa decidir rapidamente, para cada lote, entre três destinos:

  • Premium: engarrafar com rótulo de reserva, preço maior;
  • Padrão: linha comercial regular;
  • Revisar: encaminhar para prova sensorial antes de liberar, com possível corte ou descarte.

Os dados vêm do conjunto Wine Quality do Repositório UCI (Cortez et al., 2009): 1.599 vinhos tintos da região do Vinho Verde, cada um com 11 medições de laboratório e a mediana das notas de pelo menos três provadores, numa escala de 0 a 10. Na prática, as notas vão de 3 a 8, e 83 % dos vinhos receberam 5 ou 6.

  • SE álcool é alto E acidez é baixa ENTÃO qualidade é excelente
  • SE álcool é médio E acidez é média ENTÃO qualidade é regular
  • SE acidez é alta ENTÃO qualidade é ruim

03 · IMPLEMENTAÇÃOConstruindo o sistema em Python

Usamos a biblioteca scikit-fuzzy, que implementa funções de pertinência, operadores e um módulo de controle (skfuzzy.control) pronto para sistemas Mamdani. A instalação é pip install scikit-fuzzy pandas.

Passo 1. Carregar os dados

carregar.py
import numpy as np, pandas as pd
import skfuzzy as fuzz
from skfuzzy import control as ctrl

URL = ("https://archive.ics.uci.edu/ml/machine-learning-databases/"
       "wine-quality/winequality-red.csv")
df = pd.read_csv(URL, sep=";")      # 1599 linhas x 12 colunas
print(df.corr(method="spearman")["quality"].sort_values())

Passo 2. Variáveis linguísticas e funções de pertinência

Antecedent são entradas e Consequent é a saída. trapmf recebe os quatro vértices do trapézio e trimf os três do triângulo.

variaveis.py
alcool   = ctrl.Antecedent(np.arange(8, 15.01, 0.01), "alcool")
acidez   = ctrl.Antecedent(np.arange(0.1, 1.601, 0.005), "acidez")
sulfatos = ctrl.Antecedent(np.arange(0.3, 2.001, 0.005), "sulfatos")
qualidade = ctrl.Consequent(np.linspace(0, 10, 501), "qualidade",
                            defuzzify_method="centroid")

alcool["baixo"] = fuzz.trapmf(alcool.universe, [8, 8, 9.5, 10.5])
alcool["medio"] = fuzz.trimf(alcool.universe, [9.5, 10.5, 11.6])
alcool["alto"]  = fuzz.trapmf(alcool.universe, [10.6, 11.8, 15, 15])

acidez["baixa"] = fuzz.trapmf(acidez.universe, [0.1, 0.1, 0.35, 0.5])
acidez["media"] = fuzz.trimf(acidez.universe, [0.35, 0.58, 0.95])
acidez["alta"]  = fuzz.trapmf(acidez.universe, [0.7, 1.0, 1.6, 1.6])

sulfatos["baixo"]     = fuzz.trapmf(sulfatos.universe, [0.3, 0.3, 0.48, 0.6])
sulfatos["adequado"]  = fuzz.trapmf(sulfatos.universe, [0.55, 0.68, 0.85, 1.0])
sulfatos["excessivo"] = fuzz.trapmf(sulfatos.universe, [0.9, 1.1, 2.0, 2.0])

qualidade["ruim"]      = fuzz.trapmf(qualidade.universe, [2, 3, 3.5, 5])
qualidade["regular"]   = fuzz.trimf(qualidade.universe, [4, 5.2, 6.2])
qualidade["boa"]       = fuzz.trimf(qualidade.universe, [5.4, 6.4, 7.4])
qualidade["excelente"] = fuzz.trapmf(qualidade.universe, [6.6, 7.6, 9, 9])

Passo 3. Base de regras

Os operadores &, | e ~ correspondem a E (mínimo), OU (máximo) e NÃO (complemento).

regras.py
regras = [
    ctrl.Rule(alcool["alto"] & acidez["baixa"], qualidade["excelente"]),
    ctrl.Rule(alcool["alto"] & sulfatos["adequado"], qualidade["excelente"]),
    ctrl.Rule(alcool["alto"] & acidez["media"], qualidade["boa"]),
    ctrl.Rule(alcool["medio"] & acidez["baixa"] & sulfatos["adequado"],
              qualidade["boa"]),
    ctrl.Rule(alcool["medio"] & acidez["media"], qualidade["regular"]),
    ctrl.Rule(alcool["medio"] & sulfatos["baixo"], qualidade["regular"]),
    ctrl.Rule(alcool["baixo"] & acidez["baixa"], qualidade["regular"]),
    ctrl.Rule(alcool["baixo"] & acidez["media"], qualidade["regular"]),
    ctrl.Rule(alcool["baixo"] & sulfatos["baixo"], qualidade["ruim"]),
    ctrl.Rule(acidez["alta"], qualidade["ruim"]),
    ctrl.Rule(sulfatos["excessivo"], qualidade["regular"]),
]
sistema = ctrl.ControlSystem(regras)

Passo 4. Inferência e decisão

decidir.py
def indice(alc, va, sul):
    sim = ctrl.ControlSystemSimulation(sistema)
    sim.input["alcool"], sim.input["acidez"], sim.input["sulfatos"] = alc, va, sul
    sim.compute()
    return sim.output["qualidade"]

LIM_PREMIUM, LIM_REVISAR = 6.6, 4.6     # definidos pela gestão

def decisao(i):
    if i >= LIM_PREMIUM: return "Premium"
    if i < LIM_REVISAR:  return "Revisar"
    return "Padrão"

print(indice(12.5, 0.30, 0.75))   # 8.03  -> Premium
df["indice"] = [indice(a, v, s) for a, v, s in
                zip(df.alcohol, df["volatile acidity"], df.sulphates)]
df["decisao"] = df.indice.map(decisao)

04 · VANTAGENS E LIMITAÇÕESQuando a lógica fuzzy é a ferramenta certa

Vantagens

  • Interpretável. Cada decisão pode ser explicada pelas regras que dispararam e com que força.
  • Funciona sem dados rotulados. O conhecimento vem do especialista; os dados servem para validar.
  • Resposta suave. Pequenas variações nas entradas geram pequenas variações na saída, sem degraus arbitrários.
  • Tolera imprecisão. Lida bem com medições ruidosas e com conceitos vagos como "alto" ou "adequado".
  • Fácil de ajustar. Mudar uma regra ou um vértice não exige retreinar nada.

Limitações

  • Explosão de regras. Com n variáveis de 3 termos, a base completa tem 3n regras. Acima de 4 ou 5 entradas fica inviável manter à mão.
  • Depende do especialista. Funções e regras mal calibradas produzem resultados ruins, e não há garantia de ótimo.
  • Menor poder preditivo. Modelos como random forest costumam errar menos quando há muitos dados rotulados.
  • Sem validação formal embutida. A qualidade precisa ser medida à parte, como fizemos com Spearman e AUC.
  • Custo de centroide. Mamdani com integração numérica é mais lento que Sugeno em sistemas de tempo real.

Use lógica fuzzy quando o problema tiver poucas variáveis, conhecimento especialista disponível, conceitos naturalmente vagos e necessidade de explicar a decisão: controle de processos, triagem, classificação de risco, avaliação de fornecedores, priorização de chamados. Prefira aprendizado de máquina quando houver muitas variáveis, muitos dados rotulados e a precisão importar mais que a explicação. Os dois também se combinam: sistemas neuro-fuzzy como o ANFIS aprendem as funções de pertinência a partir dos dados mantendo as regras legíveis.

05 · APLICAÇÃO EM SADDo índice à decisão do gestor

Um Sistema de Apoio à Decisão não decide sozinho: ele organiza dados e modelos para que pessoas decidam melhor. O índice fuzzy alimenta os três níveis de decisão da vinícola.

Operacionaldia a dia da linha

Cada lote recebe índice e destino assim que sai do laboratório. Só os lotes marcados como Revisar vão para a prova sensorial, o que concentra o tempo dos provadores onde há risco.

Gerencialtático, por safra

O gerente de qualidade ajusta os limiares conforme a política do período: mais exigência no Premium protege a marca, menos exigência aumenta o volume de reserva. O painel abaixo simula esse trade-off com os 1.599 lotes.

Estratégicolongo prazo

As regras mostram o que puxa a qualidade para baixo. Se muitos lotes caem por acidez alta, a direção sabe que investir em higiene de tanques e controle de fermentação rende mais que comprar uvas mais caras.

É aqui que a lógica fuzzy mostra seu valor em SAD. O sistema não entrega só um rótulo: entrega um índice contínuo, as regras que o justificam e um ponto de ajuste que pertence ao gestor, não ao algoritmo. A decisão continua humana, mas passa a ser rápida, consistente e auditável.

Para levar

  • Lógica fuzzy modela conceitos vagos com graus de pertinência entre 0 e 1.
  • O sistema Mamdani segue quatro passos: fuzzificar, avaliar regras, agregar e defuzzificar.
  • Com 3 medições e 11 regras sem treino, chegamos a Spearman 0,55 e AUC 0,85 nos dados reais.
  • Em SAD, o valor está na explicação das decisões e na possibilidade de o gestor ajustar a política.
